## Summary
A custody/storage ledger for client-owned semen straws — we do not sell straws. Two sourcing paths; straws must arrive before a protocol.

## Spec references
- §5.6 (semen inventory), §10b (Semen straws)

## Requirements
- `semen_inventory`: sire, breed, straws_count, source (client|jeff), source_contact, location, owned_by (always client), storage_start, storage_free_until, receipt_fee_charged.
- Intake logs a shipment ($15 receipt fee).

## Acceptance criteria
- [ ] **We do NOT sell straws** — custody/storage only; **`owned_by` is always the client** (§5.6).
- [ ] **Client-sourced** path: client ships to the farm; system provides intake info (shipping address, tank details, timing); **straws must arrive BEFORE the protocol** (booking prerequisite) (§5.6).
- [ ] **Jeff-sourced** path: capture bank/bull, contact, and who to pay (§5.6).
- [ ] Intake logs a shipment and charges the **$15 receipt fee** (from `rate_config`) (§5.6, 8.2).
- [ ] Storage **free year 1 with AI, then $50/yr** (≤10 straws) tracked via `storage_free_until` (from `rate_config`).
- [ ] **Straws never expire — no expiry tracking, no shelf-life warnings** (§10b).

## Mobile behavior
Simple intake form; big tap targets; scan/tap straw counts.

## Config over code
Receipt/storage fees from `rate_config`; no hardcoded prices.

## Tests
- Intake increments count + charges receipt fee once per shipment.
- Storage free-until set for AI clients; no expiry logic anywhere.

## Definition of done
Custody ledger with both sourcing paths, receipt fee, storage year tracking; no expiry.
