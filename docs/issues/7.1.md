## Summary
The keystone form Jeff fills at/after each visit. It drives inventory, records, and accounting. Mobile-first, one-handed, gloves-on in a barn.

## Spec references
- §5.5 (Appointment completion form), §5.6b, §5.6c, §10b — binding.

## Requirements
- Writes `visit_completions` (`completed_at`, `procedure_confirmed`, `semen_inventory_id`, `straws_used`, `straws_wasted`, `supplies_used`, `mileage`, `notes`) and appends to `health_records`; attaches `media`.

## Acceptance criteria
- [ ] Confirms **procedure performed** + **actual completed timestamp** (authoritative; V3 recomputes from it — see 1.3).
- [ ] On AI visits: **select which straw/sire was used → decrement `semen_inventory` by 1**; a wasted straw is logged **separately** as waste.
- [ ] **BCS 1–9 per animal is REQUIRED on breeding-related visits** (5–6 target); stored on `health_records.bcs_score` with date + visit.
- [ ] Supplies consumed default from the service usage profile (5.2), manually adjustable; **mileage** captured.
- [ ] Photos + notes attach to the animal (and optionally the visit); notes written to records automatically.

## Mobile behavior
- [ ] Big tap targets, minimal typing, steppers/toggles over free text; usable one-handed with gloves.

## Config over code
Supply defaults come from `supply_usage_profiles`; timing recompute uses `config/protocol.php`.

## Tests
- [ ] Straw used decrements inventory by 1; wasted straw decrements + flags waste separately.
- [ ] BCS required on breeding visits (validation blocks submit without it).
- [ ] Completion writes the authoritative timestamp used by V3 recompute.

## Definition of done
Drives inventory + records + COGS; BCS enforced; mobile-first verified.
