TITLE: 4.2 — Health records
MILESTONE: M4 — Herd records portal
LABELS: devin,records
---
## Summary
Per-animal health record log with strict edit-permission rules and attribution.

## Spec references
- §5.5, §6, §10b (Records, permissions, data lifecycle)

## Requirements
- `health_records` types: vaccination, treatment, nutrition, dehorning, preg_check, body_condition, general.
- Attribution via `added_by` / `added_role`.

## Acceptance criteria
- [ ] **Clients CANNOT edit or delete staff-added records** — Jeff's farm records are his professional record (audit integrity) (§10b).
- [ ] **Jeff CAN edit client-added records, with changes attributed to him** (§10b).
- [ ] Vet visibility respects the client-selected `vet_scope` (3.3).
- [ ] BCS entries store score (1–9) + date + `visit_id` (feeds 10.2).
- [ ] Nothing hard-deletes (soft-delete only) (§10b).

## Mobile behavior
Quick-add record types via large buttons; minimal typing; readable timeline.

## Config over code
Record types enumerable; no hardcoded pricing.

## Tests
- Client edit/delete of a staff record is blocked.
- Jeff edit of a client record is attributed.
- Vet sees only in-scope record types.

## Definition of done
Health records with permission rules + attribution enforced; tests green.
