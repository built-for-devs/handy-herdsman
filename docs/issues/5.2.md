## Summary
Jeff's own working stock, tracked so he isn't caught short mid-season. Consumption estimated from completion forms; low-stock alerts; unit costs feed COGS.

## Spec references
- §5.6b (Supply & consumables inventory)

## Requirements
- `supplies`: item, category, unit, on_hand, low_stock_threshold, unit_cost, is_prescription, notes.
- `supply_usage_profiles`: per-service default consumables (json), auto-decrement on completion, adjustable.

## Acceptance criteria
- [ ] Track Jeff's stock: needles, syringes, sleeves/gloves, lubricant, antiseptic, **CIDRs, GnRH, prostaglandin**, prescription meds, ear tags, etc. (§5.6b).
- [ ] Consumption **estimated from the completion form** via each service's `supply_usage_profiles` (e.g. sync protocol = 1 CIDR + 2 GnRH + 1 PG + sleeves/gloves), auto-decremented, **manually adjustable** when actual differs (§5.6b, 7.1).
- [ ] **Low-stock thresholds per item → alerts** Jeff to reorder (§5.6b).
- [ ] **Unit cost per item** stored → feeds COGS (§5.6c, 10.1).
- [ ] Prescription meds flagged separately (sourcing/expiry).
- [ ] Deliberately lightweight — directional estimates over precise counts.

## Mobile behavior
Quick stock adjust; low-stock badge list; big tap targets.

## Config over code
Usage profiles are editable data (`supply_usage_profiles`).

## Tests
- Completion decrements per profile; manual override respected.
- On_hand crossing threshold raises a low-stock alert.

## Definition of done
Stock tracked, profile-driven decrements, low-stock alerts, unit costs for COGS.
