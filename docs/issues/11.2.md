## Summary
The lightest viable dispatch aid — a day/route view of scheduled visits with distance flags. Explicitly not an optimization engine. Build last.

## Spec references
- §5.10 (Dispatch / routing)

## Requirements
- Day/route view of scheduled visits using geocoded client locations (cached at onboarding).

## Acceptance criteria
- [ ] Day/route view of scheduled visits so Jeff isn't crisscrossing (§5.10).
- [ ] Auto-flag out-of-range clients + surface the distance fee at booking (§5.10, 6.6).
- [ ] **Explicitly NOT a territory-day optimization engine** — map + distance flag + fee trigger is enough until density justifies more (§5.10).
- [ ] Uses geocoded/cached client distances (no new geocoding calls) (§5.10).

## Mobile behavior
Map + ordered day list; tap for directions; big targets.

## Config over code
Farm origin + thresholds from config/`service_area_rules`.

## Tests
- Day view lists scheduled visits with distance flags.

## Definition of done
Day/route view + distance flags; no optimization engine; built last.
