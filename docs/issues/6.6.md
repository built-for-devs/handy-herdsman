TITLE: 6.6 — Distance fee & service area
MILESTONE: M6 — Booking & scheduling
LABELS: devin,booking
---
## Summary
Flag out-of-range clients and apply the distance fee per booking. Distance cached at onboarding.

## Spec references
- §2, §10b (Money), §5.10

## Requirements
- Use `service_area_rules` (15mi threshold, $30 fee) + cached client distance.

## Acceptance criteria
- [ ] **Distance fee is PER BOOKING/PROTOCOL, not per visit** — one $30 covers all three protocol visits (§10b).
- [ ] Over 15mi flags the fee (from `service_area_rules`); **declined zones are blocked/flagged** for a manual decision (§2, §10b).
- [ ] Distance is **geocoded + cached at onboarding**; Distance Matrix is called sparingly (cost control) (§5.10, §9).
- [ ] Fee amounts + threshold from `service_area_rules`/`rate_config`, editable without deploy (§7).

## Mobile behavior
Distance-fee shown transparently before confirming a booking.

## Config over code
Thresholds + fees in `service_area_rules`/`rate_config`.

## Tests
- 20mi client → one $30 fee on a 3-visit protocol (not $90).
- Declined zone → blocked/flagged.

## Definition of done
Per-booking distance fee from config; declined-zone handling; cached distance.
