## Summary
The recurring-revenue and retention engine: the rebreed loop, data-driven nudges, seasonal, and referral messages. Content does double duty with the blog.

## Spec references
- §5.7 (full catalog)

## Requirements
- Implement the remaining catalog categories (herd follow-ups cat.3, seasonal/content + retention + referral cat.4).

## Acceptance criteria
- [ ] **Post-calving rebreed loop** (post-calving +30d timeline, +45–60d direct rebreed prompt) — the **core recurring-revenue loop** (§5.7).
- [ ] Didn't-settle rebook (preg check `open` → rebook AI now) (§5.7, 7.3).
- [ ] **Data-driven** nudges from logged records: no minerals/salt ("#1 reason AI fails"), **BCS out of range → nutrition follow-up**, storage nearing 1yr, straws unused 6mo+ (§5.7).
- [ ] Seasonal (pre-breeding, pre-winter minerals, annual boosters, fly/parasite), retention (dormant re-engagement, post-visit review/referral ask, anniversary), referral/growth (§5.7).
- [ ] Nurture emails **pull from blog content** (2.3) so content does double duty (§5.7).
- [ ] Category defaults + consent honored via 9.2; cat.4 promotional requires opt-in.

## Config over code
Templates/offsets as data; blog content from `posts`.

## Tests
- Post-calving schedules the rebreed prompts.
- BCS flagged out-of-range at last visit → nutrition follow-up queued.
- open preg result → rebook prompt.

## Definition of done
Rebreed loop + data-driven + seasonal + retention + referral; pulls blog content; consent honored.
