TITLE: 3.3 — Team invitations (spouse + vet)
MILESTONE: M3 — Clients, teams, onboarding
LABELS: devin,clients
---
## Summary
Owners invite a member (spouse) or a read-only vet, with client-controlled vet scope. Built on Spatie teams mode.

## Spec references
- §4, §10b (Notification recipients; records/permissions)

## Requirements
- Owner invites via `team_invitations` (email, role member|vet, token, status, `vet_scope` json).
- Member = full access to that team's records. Vet = read-only on cattle profiles, scope client-selected.

## Acceptance criteria
- [ ] Owner can invite a **member (full access)** or a **vet (read-only)**.
- [ ] **Vet read scope is client-controlled per invitation** (`vet_scope`): profile only, or profile + chosen record types (§10b — resolves the §4/§5.2 conflict; client decides).
- [ ] Vet has **no** booking/billing/inventory writes (§4).
- [ ] **Vets never receive automated client notifications** (§10b).
- [ ] **Team owner receives all client notifications by default; invited members receive nothing until they opt in themselves** (§10b, 3.4).
- [ ] Built on Spatie teams mode — no custom permission engine (§4).

## Mobile behavior
Simple invite form (email + role); accept flow works on phone.

## Config over code
Roles from Spatie; scope stored as data.

## Tests
- Member invite → full team access; vet invite → read-only within scope.
- Vet cannot write; vet excluded from notifications.

## Definition of done
Member + scoped read-only vet invitations via Spatie; notification defaults enforced.
