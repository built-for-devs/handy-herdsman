## Summary
The `clients.status` lifecycle that gates self-booking.

## Spec references
- §10b (Client status; Bookings/cancellation SLA)

## Requirements
- Status enum: `new` → `active` → `inactive`.
- Track `last_activity_at` to drive idling.

## Acceptance criteria
- [ ] `new` → first appointment **requires staff review** (24h SLA); client sees provisional status clearly (§10b).
- [ ] `new` → `active` **automatically after ONE completed visit**; active clients book freely, no approval (§10b).
- [ ] `active` → `inactive` after **1 year of no activity**; a returning inactive client's next booking **reverts to requiring approval** (§10b — conditions change: moved, new herd, new containment).
- [ ] Status transitions are driven by events (visit completion, inactivity), not manual guesswork.

## Config over code
SLA window and idle threshold as config values.

## Tests
- New client's first booking flagged for review; after one completed visit → active.
- Active client with 366 days idle → inactive; next booking requires approval.

## Definition of done
Status machine drives the self-booking gate per §10b; tests green.
